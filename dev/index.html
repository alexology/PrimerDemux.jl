PrimerDemux.jl

Primer and adapter removal and demultiplexing of FASTQ/FASTA reads in native Julia, in the style of cutadapt by Marcel Martin. The alignment algorithm, its k-mer pre-filter, the rules that choose between matches and the order of modifications and filters are translated from cutadapt 5.2; the interface is a Julia API with keyword arguments instead of a command line.

This package is part of an experimental effort to use AI to port bioinformatics and quantitative ecology packages to Julia, with the goal of creating a unified environment for high performance scientific computing.

With equivalent options the output is identical to cutadapt 5.2 on the 41 scenarios of the test suite and on a real Oxford Nanopore sample (see Validation), and it does not depend on the number of threads.

Julia ≥ 1.10 (tested with 1.12). Dependencies: FASTX.jl (FASTQ/FASTA parsing), CodecZlibNG.jl (gzip input, zlib-ng), libdeflate_jll (gzip output), TranscodingStreams.jl, StringViews.jl.

Installation

The package is not registered. Install it from GitHub:

using Pkg
Pkg.add(url = "https://github.com/alexology/PrimerDemux.jl")

Quick start

using PrimerDemux

# Linked, anchored primers on both strands; reads without them are dropped
# (cutadapt --revcomp -g ^FWD...REV_RC --discard-untrimmed)
primers = front_adapter("^AAGCTWMTGGGTTCATACCC...GTGCAATGGATTTAAGCTCCA")
stats = remove_primers("sample.fastq.gz", "sample.trimmed.fastq.gz";
                       adapters = primers, revcomp = true, discard_untrimmed = true)

# Demultiplexing by anchored 5' barcodes from a FASTA file
# (cutadapt -g ^file:barcodes.fasta -o "{name}.fastq.gz")
demultiplex("pool.fastq.gz", "demux/{name}.fastq.gz";
            adapters = adapters_from_fasta("barcodes.fasta"; anchored = true))

# Paired-end: primers in R1 and R2, pairs shorter than 100 bp dropped
remove_primers(("R1.fastq.gz", "R2.fastq.gz"), ("out_R1.fastq.gz", "out_R2.fastq.gz");
               adapters = front_adapter("^GGWACWGGWTGAACWGTWTAYCCYCC"),
               adapters2 = front_adapter("^TAAACTTCAGGGTGACCAAAAAATCA"),
               discard_untrimmed = true, min_length = 100)

Both functions return a TrimStats summary (printed like cutadapt's report).

The specification syntax is cutadapt's: "name=SEQUENCE" sets the name used in reports and for demultiplexing (default: the specification itself), ";e=0.15;o=5;noindels" overrides the search parameters of one adapter, ";required"/";optional" apply to the parts of linked adapters, "A{10}" repeats a base. IUPAC codes in adapters are wildcards.

Processing files

remove_primers(input, output; ...) writes one output (two for pairs); demultiplex(input, "dir/{name}.fastq.gz"; ...) writes one file per adapter name, plus unknown for reads without a match (or untrimmed_output, or nothing with discard_untrimmed = true). For pairs, {name} follows R1, while {name1} and {name2} in both paths route by the combination of R1 and R2 matches.

Inputs may be FASTQ or FASTA, plain or gzip. Outputs are gzip when the name ends in .gz, FASTA when it ends in .fasta, .fa, .fna or .fas. Outputs are written to temporary files in the same directory and renamed into place at the end; an error leaves no partial output, and replaced files are restored if putting the outputs in place fails (a crash during those final renames is not covered; if the file system prevents a restore, the previous content is kept in a temporary file whose name is logged). Existing files are kept unless overwrite = true, also when they appear while the run is in progress. Outputs that would be the same file (also through links, or names differing only in case on Windows and macOS) or an input are refused. As in cutadapt, paired inputs must have matching read IDs, up to a final 1, 2 or 3.

Order of the steps, as in cutadapt: unconditional cuts, quality trimming, adapters (with the reverse complement if requested), then the filters too short, too long, too many N, too many expected errors, and finally trimmed or untrimmed reads.

For single sequences, find_adapter(adapters, seq) returns the best AdapterMatch and trim_sequence(adapters, seq; times, action, revcomp) the trimmed sequence.

Differences from cutadapt

  • Not available: -b (anywhere) and ;rightmost adapters, --action=crop, NextSeq/poly-A trimming, --trim-n, --length, renaming templates, info and JSON report files, --times with pair_adapters, colorspace, bzip2/xz.
  • The index cutadapt builds for several anchored adapters (an optimisation with its own rules for ambiguous sequences) is not used: results equal cutadapt with --no-index. With many similar barcodes cutadapt's default may assign some reads differently.
  • Adapter names default to the specification, not to "1", "2", ...
  • When a 5' search window of the k-mer pre-filter extends past the end of a short read, cutadapt reads past the string (an undefined result); PrimerDemux then always runs the aligner. No difference was observed.
  • Gzip outputs consist of one gzip member per batch (like parallel gzip tools); the decompressed content is the same.
