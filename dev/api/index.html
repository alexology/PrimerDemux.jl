API

PrimerDemux.PrimerDemux — Module
PrimerDemux

Primer and adapter removal and demultiplexing of FASTQ/FASTA reads in the style of cutadapt, with a Julia API. The alignment algorithm, its k-mer pre-filter and the rules that choose between matches are translated from cutadapt 5.2.

Main entry points: remove_primers and demultiplex for files; front_adapter, back_adapter and adapters_from_fasta to describe what to search; find_adapter and trim_sequence for single sequences.

Processing files

PrimerDemux.remove_primers — Function
remove_primers(input, output; adapters, kwargs...) -> TrimStats

Remove adapters or primers from the reads of input (FASTQ or FASTA, plain or gzip) and write them to output (gzip when the name ends in .gz; FASTA when it ends in .fasta, .fa, .fna or .fas). For paired-end data give tuples: remove_primers(("R1.fq.gz", "R2.fq.gz"), ("o1.fq.gz", "o2.fq.gz"); ...). Outputs are written to temporary files and renamed into place at the end; existing files are kept unless overwrite=true.

Adapters (see front_adapter, back_adapter, adapters_from_fasta):

  • adapters: searched in R1 (cutadapt -a/-g); adapters2: in R2 (-A/-G).
  • times=1: removal rounds (-n); action=:trim (:retain, :mask, :lowercase, :none) as --action.
  • revcomp=false: also try the reverse complement and keep the better orientation (--revcomp); rc_suffix=" rc" is appended to the names of reversed reads. For pairs, R1 and R2 are swapped instead.
  • pair_adapters=false: adapters[i] and adapters2[i] must be found together (--pair-adapters).

Other modifications, applied before the adapters: cut/cut2 (-u/-U, an integer or a vector of up to two), quality_cutoff/quality_cutoff2 (-q/-Q, 20 or (front, back); without quality_cutoff2, R2 uses quality_cutoff, as cutadapt), quality_base=33.

Filters, applied after trimming in this order: min_length (-m), max_length (-M) — integers, or (R1, R2) tuples with nothing for no limit —, max_n (--max-n, a count or a fraction below 1), max_expected_errors (--max-ee), then one of discard_trimmed, discard_untrimmed or untrimmed_output (path, or tuple for pairs). pair_filter (:any, default, :both, :first) decides when a pair is filtered; for untrimmed pairs it is :both when adapters are searched in only one mate, as in cutadapt.

threads (default Threads.nthreads()), batch_size=4096 reads per batch, compression_level=1 for gzip outputs (libdeflate, 0–12).

PrimerDemux.demultiplex — Function
demultiplex(input, output; adapters, kwargs...) -> TrimStats

Like remove_primers, but every read goes to the file of the adapter that matched it (in the last removal round): output must contain {name}, replaced by the adapter name. Reads without a match go to {name} = "unknown", to untrimmed_output if given, or are dropped with discard_untrimmed=true. One file is created for every adapter name, also when it receives no reads.

For paired-end data output is a tuple. With {name} the R1 match decides; with {name1} and {name2} in both paths, pairs are routed by the combination of the R1 (adapters) and R2 (adapters2) matches, "unknown" standing for a missing match (combinatorial demultiplexing).

PrimerDemux.TrimStats — Type
TrimStats

Summary returned by remove_primers and demultiplex. Counts refer to reads (single-end) or pairs (paired-end); bp_in/bp_out sum both mates. with_adapters[i] and adapter_matches[i] refer to mate i. written gives the reads or pairs written to each output (by name for demultiplexing, "untrimmed" for untrimmed_output).

Describing adapters and primers

PrimerDemux.front_adapter — Function
front_adapter(spec; name, max_errors=0.1, min_overlap=3, indels=true,
              adapter_wildcards=true, read_wildcards=false) -> Adapter

5' adapter or primer, as cutadapt -g spec. The specification follows the cutadapt syntax:

  • "ACGT" regular 5' adapter, "^ACGT" anchored, "XACGT" non-internal;
  • "name=ACGT" gives the name used in reports and for demultiplexing (default: the specification itself);
  • "ACGT...TTGC" linked adapter (5' part then 3' part, both required with front_adapter), e.g. "^FWDPRIMER...REVPRIMER_RC$";
  • ";e=0.2;o=5;noindels" and, in linked parts, ";required"/";optional" override the keyword defaults for one adapter;
  • "A{5}" expands to "AAAAA"; IUPAC codes are wildcards in the adapter.

max_errors is an error rate below 1 and an absolute number of errors from 1 upwards, as in cutadapt -e.

source
PrimerDemux.back_adapter — Function
back_adapter(spec; kwargs...) -> Adapter

3' adapter or primer, as cutadapt -a spec: "ACGT" regular, "ACGT$" anchored, "ACGTX" non-internal. In a linked adapter ("ACGT...TTGC") only anchored parts are required by default. See front_adapter for the syntax and the keywords.

source
PrimerDemux.adapters_from_fasta — Function
adapters_from_fasta(path; type=:front, anchored=false, kwargs...) -> Vector{Adapter}

One adapter per FASTA record, named after the record identifier, as cutadapt -g file:path (type=:front) or -a file:path (type=:back). anchored=true corresponds to -g ^file:path and -a file$:path. Records may use the full specification syntax (for example linked FWD...REV). Typical use: a FASTA of sample barcodes or primer pairs for demultiplex.

SingleAdapter

PrimerDemux.LinkedAdapter — Type
LinkedAdapter

A 5' adapter followed by a 3' adapter (FRONT...BACK): the 5' part is searched first, the 3' part in what remains after it. Both parts are removed. Build it with front_adapter or back_adapter and a ... in the specification.

source
PrimerDemux.Placement — Type
Placement

Where a single adapter is searched (cutadapt option and syntax in brackets):

  • FRONT: 5' adapter anywhere in the read, also partial at the 5' end (-g ADAPTER); the adapter and everything before it are removed.
  • BACK: 3' adapter anywhere in the read, also partial at the 3' end (-a ADAPTER); the adapter and everything after it are removed.
  • PREFIX: anchored 5' adapter, must be at the very start and complete (-g ^ADAPTER).
  • SUFFIX: anchored 3' adapter, must be at the very end and complete (-a ADAPTER$).
  • FRONT_NOT_INTERNAL: 5' adapter that may be partial but must start the read (-g XADAPTER).
  • BACK_NOT_INTERNAL: 3' adapter that may be partial but must end the read (-a ADAPTERX).

Single sequences

PrimerDemux.find_adapter — Function
find_adapter(adapters, seq) -> Union{Nothing,AdapterMatch}

Best match of adapters (one adapter or a vector) in the sequence seq, with the same rules as the file functions (highest score, then fewest errors, then first adapter). m.adapter is the index of the matching adapter; PrimerDemux.score(m) and PrimerDemux.errors(m) give score and errors.

source
PrimerDemux.AdapterMatch — Type
AdapterMatch

Result of matching an adapter to a read. adapter is the index of the adapter in the searched list. front/back are the parts that removed sequence before or after the match (nothing when absent). Coordinates are 0-based and half-open on the sequence the part was searched in (for the 3' part of a linked adapter, the read after removal of the 5' part).

source
PrimerDemux.trim_sequence — Function
trim_sequence(adapters, seq; times=1, action=:trim, revcomp=false)
    -> (sequence, matches, reverse_complemented)

Adapter removal on one sequence, as done for each read by remove_primers. With revcomp=true the returned sequence is the reverse complement when that orientation matched better.

source
PrimerDemux.reverse_complement — Function
reverse_complement(seq::AbstractString) -> String

Reverse complement of a nucleotide sequence; IUPAC codes are complemented, case is preserved and other characters are kept as they are.

source
PrimerDemux.quality_trim_index — Function
quality_trim_index(qualities, cutoff_front, cutoff_back; base=33) -> (start, stop)

BWA-style quality trimming as in cutadapt -q front,back: 0-based half-open interval of the part to keep. base can also be given as a fourth positional argument.
